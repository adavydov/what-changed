Chapter 01

Where control lives now

Story 01

The human tired of being the allow button

On August 14, Claude Code made auto mode the default for new Pro, Max, and Team sessions unless a user or administrator had pinned another mode. Instead of asking before every command, it sends each action through a classifier looking for irreversible, destructive, or external operations.

The reason is not speed alone. Anthropic says people approve 97% of permission prompts but reject 39% of plans proposed by the agent. A person can still judge the direction of the work, yet becomes much worse at spotting one dangerous command in a stream of routine confirmations.

In a controlled experiment with 1,053 paid testers, people noticed 13.6% of substituted dangerous commands; the classifier caught 89%. Human blocking fell from about 17% early in a session to 5% after 50 or more earlier prompts. The machine's rate did not decline.

The same pattern appeared in a selected sample of real sessions: unintended production-severity harm occurred in 6.3% of manual-approval sessions and 2.4% of auto-mode sessions. These were sessions already flagged by a safety system for review, however, not the full population.

The classifier does not silently block the whole job. The agent can find a safer route or ask for an exception. After 3 consecutive blocks or 20 within a session, Claude Code falls back to manual approvals. Control becomes an escalation path instead of a row of identical buttons.

For a company, that changes the unit of oversight. Hard denies, trusted destinations, environment boundaries, and stop conditions must be set in advance. Humans should approve the plan, an unusual exception, and an outcome with a high cost of error—not simulate attention at every step.

All figures and the analysis come from Anthropic. The controlled study replaced only the displayed command text, and the red-team attacks were synthetic. A classifier can still fail, so the authors themselves recommend human review for actions in critical production infrastructure.

Story 02

The specification became the acceptance surface

In a case study published on August 12, an agent dismantled a core architectural invariant in a TypeScript application containing 717,725 lines and 3,648 files. No human performed code review, and no ready-made test oracle existed. At first glance, those are poor conditions for an autonomous migration.

The author moved control into a separate contract. The agent first compared a formal specification with the actual code and refined it through 14 cycles. The specification was then frozen, the change was implemented atomically, and 17 further cycles searched the result for deviations from that same text.

There were 31 audit passes in total. Before a person first ran the program, the agent had corrected 201 discovered defects. The stop rule was 2 consecutive passes with no new findings. The author calls this convergence, not proof that no defects remained.

The migration touched 189 files, or 288 when common-code extraction is included. The report says it took 3 days and cost $2,430 in model calls. The central result is not the speed. A new patch could previously alter the success criterion without notice; freezing the text closed that escape route.

This protocol changes the role of a manager and engineer. Before work begins, they need an acceptance contract precise enough for a separate agent to attack the outcome without sharing the implementer's memory. The human accepts the contract and the evidence, not every line.

There is an important limit: this is one author, one codebase, with no control group or independent review. Agents that write and check code may share the same blind spots. The case demonstrates that the protocol can operate; it does not establish error-free autonomous development.

Chapter 02

What crosses the boundary

Story 03

A capability detached from one agent

On August 12, GitHub added Agent Plugins 1.0 support across VS Code, Copilot CLI, the Copilot SDK, and the Copilot app. One package can now carry skill instructions and MCP server configuration into several compatible agent clients. Copilot-specific extensions remain in a separate namespace.

Before the standard, teams could distribute the same runbook-and-tool pair across agents, but each client required different packaging. Portability turns the plugin into a system component in its own right. Changing the chat surface or model no longer means changing the working method or its access to systems.

In GitHub's implementation, control follows that portability. An administrator can automatically install or block a plugin, constrain approved marketplaces, and separately allow or deny MCP servers by URL, command, or name. Policy becomes a wrapper around the capability rather than a fresh configuration for every interface.

The practical consequence is that a registry of agents is not enough. A company also needs a registry of capabilities: owner, version, provenance, permitted tools, environments, and data. Otherwise one approved package quietly expands the action surface in every compatible client.

This is not yet universal interoperability. The package can contain client-specific extensions, and the enterprise controls described are part of GitHub's ecosystem. The standard itself first appeared on August 6; the event this week is its availability across four GitHub products.

A portable plugin is a small example of a larger shift. As a working method separates from one model, asking which AI the company approved is no longer sufficient. It must also know which capability the AI loaded and which systems that capability can reach.

Story 04

Encrypted reasoning became a portable secret

On August 10, researchers described an unexpected boundary in proprietary APIs. An encrypted reasoning block that a client could not read could be moved across sessions, users, and models from the same provider. What looked like an opaque service detail was actually a carrier of state.

The attack exploited asymmetry within a model family. A block produced by a more capable model was injected into a weaker sibling with less stringent protections, which recovered the plaintext. The authors demonstrated paths involving APIs from Anthropic, OpenAI, and Google.

They estimated the scale using open traces. Among 315,320 reasoning blocks found in public repositories, the researchers report recovering 367 pieces of personal information and 182 credentials. They also describe hidden hazardous instructions and prompt injection carried inside opaque state.

The organizational mistake is simple: treating unreadable as non-secret. An opaque block needs labels for its source, model, session, and tenant, plus retention and replay rules. What cannot be seen in a log can still carry someone else's data and intent.

The evidence boundary matters as much as the attack. This is a preprint about closed, undocumented mechanisms. Public repositories are a selected sample, not a cross-section of all API sessions. Providers acknowledged the disclosures, and the demonstrated attacks later stopped working. That suggests mitigation, but does not prove that every variant is closed.

In the previous issue, a Word document carried an attack visible to humans and agents. The new mechanism is different: the secret hides in signed or encrypted state that the client must return to an API. Protection must therefore cover not only visible content but opaque service state.

Chapter 03

What has actually been proven

Story 05

A watermark proves participation, not authorship

On August 14, Anthropic announced that future Claude models will generate statistically watermarked text, tying the change to EU AI Act transparency rules. The mark adds no hidden characters, identifying data, or extra tokens. It only shifts the model's choice of the next word.

More important than the technique is the narrow claim. A detector can estimate whether Claude was involved in producing a text. It cannot distinguish Claude writing the document from Claude heavily editing someone else's draft. The mark speaks to provenance, not authorship, approval, or responsibility.

Anthropic says light editing may leave the signal intact, while a complete rewrite that replaces every word removes it. A translation made by Claude receives its own mark because the model selected every word. The detector measures a particular statistical trace in token choice, not abstract AI influence.

For a company, this is a lesson in the grammar of control. A positive signal can support disclosure, labeling, or a review queue. It cannot become an automatic verdict on plagiarism, deception, or who should answer for the text. One technical detector does not replace an authorship policy.

For now, this is an announcement of a future rollout, not an independent robustness evaluation. Anthropic itself says a full rewrite destroys the signal. Models released before August 2 receive a transition period under the law, so the mark will not appear across the whole product line at once.
