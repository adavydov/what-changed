Chapter 01

First move the task outside the model

Story 01

An Agent Loses the Task Between Correct Steps

Long work rarely collapses in one absurd move. An agent skips a stage, changes the wrong field, and then acts reasonably inside a corrupted state. Dozens of correct steps add up to someone else's outcome.

Workflow-GYM tested 338 professional tasks lasting from 30 to 110 actions. The best average result barely exceeded 30%. This is a score on a particular synthetic test, not the share of occupations ready for automation.

CoDA-Bench exposes a neighboring failure. The agent had to find the right data among roughly a thousand files, write code, and execute it. One strong setup identified the complete file set exactly in 83.0% of cases but produced the right final answer in only 61.1%.

When Claude Code was given the exact data paths in the hard portion of the test, its final result rose from 45.4% to 73.1%. The model stayed the same; the map of the workspace changed.

These benchmarks did not test mandates and do not reproduce an office in full. They show a narrower point: a final prompt and a click log are insufficient. The task must live outside the model, preserve state, and remind every next step whose instruction it continues.

Story 02

The Workspace Becomes the Owner of the Hands

In Xcode 27, a developer can choose among agents from Anthropic, Google, and OpenAI and connect other performers through the Agent Client Protocol. The models differ; their hands are shared.

Xcode owns those hands. The environment exposes code and active context, runs builds and tests, and opens Playgrounds, previews, and the simulator. ACP connects a compatible agent; MCP provides a channel to external tools.

The open protocol creates a double effect. Dependence on one laboratory weakens, while the power of the workspace owner grows. Switching models becomes a setting; transferring state, tools, and rules remains a migration.

Planning mode lets an agent inspect the project without modifying code, but it does not turn access into a precise mandate for the full task. Permission to run commands or enter a folder can still be broader than the instruction.

Xcode 27 is still a developer release and does not prove a productivity gain. The test comes later: if the model changes with one switch while state, permissions, and history remain in the IDE, the workspace owner has captured the durable layer.

Chapter 02

Then record authority and revocation

Story 03

Who Authorized the Agent?

An ordinary log connects calls and responses. It does not have to preserve the authority the agent spent. One task splits into retries and child performers; several instructions pass through the same service.

Abhinav Mishra and Kumar Sharad show the limit of reconstruction after the fact. The same event set can fit different chains of authority. If the link to an instruction was not recorded during execution, time stamps and session names cannot recover it honestly.

Two histories are therefore needed. One shows what technically caused the next step. The other connects the person or organization, the instruction, child agents, and the limit on further delegation. An action can enter a new process while still spending an old authority.

The preprint proposes a narrow technical start: bind each event to a stable delegation identifier, owner, and agent. A full mandate also needs the goal, permitted actions, resources, expiry, right to redelegate, and means of revocation.

The same week, Atos and Microsoft announced 19,000 agents alongside a Copilot rollout to 56,000 employees. This is a joint release with no data on active use, tasks, or incidents. Scale is a signal here, not an observed outcome.

The new management unit is already visible: companies will have to count active mandates rather than created agents. If owner, authority limit, expiry, and last irreversible action do not appear in enterprise logs, the mandate will remain an elegant diagram.

Story 04

In Payments, the Mandate Becomes a Real Object

At the checkout, the metaphor ends. The agent either had the right to spend the money or it did not.

Visa and OpenAI announced infrastructure in which a user sets a spending limit, merchant categories, and required confirmations. The agent receives tokenized credentials while the payment layer checks the transaction. The model chooses the product; the network decides whether payment is allowed.

The technical design links a credential request to a confirmed user instruction and checks the merchant and amount at authorization. After the purchase, the agent returns the result so a dispute can be tied to the original instruction.

A trusted-agent signature answers who came to the store. A mandate answers whether the person authorized this purchase, for this amount, now. The two proofs cannot substitute for each other.

Visa also describes a directory of verified agents and merchants. For now, this is announced infrastructure without disclosed agent-purchase volume. It may remain a demo or turn the payment network into the new gatekeeper for machine commerce.

The test is straightforward: a separate agent-transaction flag, instruction boundaries, and confirmation evidence must appear in authorization, refunds, and disputes. Otherwise trusted agent remains a badge rather than an institution.

Story 05

The Kill Switch Protects and Rules at the Same Time

A mandate that cannot be revoked stops being a mandate. One universal kill switch creates the reverse risk: it can stop other people's work along with dangerous use.

On June 9, NIST published an account of the argument that no fixed finite set of prompt safeguards can be treated as universally robust against every adaptive attack. The practical response is continuous search for bypasses, updating, and the ability to contain harm.

This does not mean protection is impossible. A universal guarantee for an open prompt space may be unavailable while a transfer amount, folder, expiry, or machine can still be reliably constrained by an external rule. Authority to act cannot remain inside the model's reasoning.

Three days later, Anthropic reported a US export directive that barred foreign nationals from Fable 5 and Mythos 5. The company said it disabled the two models for every customer. The directive itself was not public; AP confirmed the shutdown based on Anthropic's account.

Centralized revocation reduces dangerous access and turns an error or political conflict into downtime for innocent customers. A mature mandate must therefore be narrow, revocable, and portable: block future action, preserve evidence of the past, and let the task move to another performer.

If this layer becomes a product, platforms will begin transferring the mandate owner, limits, expiry, child instructions, and revocation status together with the task. Without that, a replaceable agent remains a button, while responsibility falls to someone who could not stop it.

Chapter 03

Another shift this week

Story 06

A Patch Starts the Clock to the Next Attack

A patch is usually treated as the end of a problem. For an attacker, it is also a clue: comparing the old and fixed versions reveals where to look for the vulnerability.

Anthropic gave Mythos Preview 18 fresh fixes for Firefox's JavaScript engine, old and new builds, and an offline test machine. For 14 fixes, the model created a working proof of vulnerability; in 8 cases, it achieved arbitrary code execution.

The first full exploit appeared in less than an hour, and all eight took about 12 hours. Even among 14 vulnerabilities predicted to have a low chance of exploitation, the model produced a working demonstration for 13.

The boundary matters. These were known targets after patch publication, not newly discovered vulnerabilities. Model safeguards were disabled, Firefox was not tested as a full browser, and target discovery, code delivery, and evasion were outside the test.

Timothée Chauvin and colleagues at Epoch AI estimate the result as roughly a seven-month jump over the previous trend. Their critique removes the scary overclaim and preserves the narrow conclusion: one part of the attack chain, building an exploit for a known target, contracted to hours.

That changes the defender's clock. Risk begins when the fix is published and ends only at the last device that is actually updated. A gradual ring rollout can leave vulnerable systems exposed longer than the model needs to create a weapon.

The practical bet is measurable: faster update rings, restartless installation where possible, and a rehearsed forced restart. Security teams need time to last patch, not the patch's release date.
